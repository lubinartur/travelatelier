# Информационная архитектура

## Основные задачи посетителя

1. Понять, какие поездки и направления агентство помогает подобрать.
2. Оценить подход, партнёров и условия, прежде чем оставить контакт.
3. Быстро передать запрос и понять следующий шаг.
4. Найти сведения о страховке, оплате и юридических условиях.

## Навигация — рекомендация

Основное меню: **Направления**, **Как мы работаем**, **Партнёры**, **Страховка**, **Контакты**. Выделенный CTA: **Подобрать поездку**. «Оплата частями», условия и конфиденциальность доступны из соответствующих блоков и подвала. На мобильном — компактное меню, постоянный доступ к CTA и переключателю языка.

## Таксономия направлений

Карточка: название ET/RU, регион/тип отдыха (только после редакторского подтверждения), изображение с правами, краткий полезный ввод, URL, статус публикации. Фильтры по целям поездки имеют смысл лишь при наличии достаточного числа подготовленных страниц. Не вводить фильтры по цене, сезону или доступности без данных и механизма обновления.

## Сценарии

- **Из вдохновения:** главная → подборка направлений → страница направления → запрос с предзаполненным направлением.
- **Из поиска:** страница направления → формат помощи и FAQ → запрос.
- **Из доверия:** «Партнёры» (подтверждённые туроператоры) и процесс → запрос. Реквизиты Travel Atelier OÜ — в футере и на `/terms` / `/privacy`.
- **Из условий:** страховка/ESTO на главной → письмо на `info@travelatelier.ee` или возврат к подбору.

## Правила структуры

Каждая публичная страница имеет один H1, прямую ссылку в релевантном месте, понятный CTA и навигационный путь. Юридические страницы не прятать за скроллом лендинга. Не смешивать юридическую информацию с продающим текстом. Языковые пары должны вести на эквивалентные страницы; при отсутствии перевода показывать ясный fallback, не автоматически другой язык.
